# Verified integration facts

Re-verified 2026-11-09 against official Stellar documentation and the current Stellar JS SDK documentation.

- `getEvents` accepts up to 5 filters and up to 5 contract IDs per request. Topic matchers contain one to four segments. `getEvents` pagination accepts limits from 1 to 10,000, default 100, and returns an opaque cursor. When using a cursor, `startLedger` and `endLedger` must be omitted. The result exposes `events`, `latestLedger`, `oldestLedger`, and `cursor`. [getEvents](https://developers.stellar.org/docs/data/apis/rpc/api-reference/methods/getEvents) [pagination](https://developers.stellar.org/docs/data/apis/rpc/api-reference/structure/pagination)
- `getHealth` returns `latestLedger`, `oldestLedger`, and `ledgerRetentionWindow`; the documented full-window relationship is `latestLedger - oldestLedger + 1`. [getHealth](https://developers.stellar.org/docs/data/apis/rpc/api-reference/methods/getHealth)
- `getNetwork` returns the configured network `passphrase`. Eventide checks every configured endpoint before indexing or serving the API. [getNetwork](https://developers.stellar.org/docs/data/apis/rpc/api-reference/methods/getNetwork)
- The official `getEvents` reference says starts below the node's oldest ledger or above its latest ledger error. The Stellar RPC issue tracker records the observed lower-bound error as JSON-RPC code `-32600` with message `start is before oldest ledger`; Eventide recognizes that exact form. [getEvents](https://developers.stellar.org/docs/data/apis/rpc/api-reference/methods/getEvents) [issue 260](https://github.com/stellar/stellar-rpc/issues/260)
- `@stellar/stellar-sdk` is the current package for Node.js Stellar RPC/XDR work. The current SDK API exposes `xdr.ScVal.fromXdr(Uint8Array)`, which Eventide uses for values and topics. [SDK](https://stellar.github.io/js-stellar-sdk/) [npm package](https://www.npmjs.com/package/@stellar/stellar-sdk)

Not verified: Stellar RPC does not define a portable provider-wide archive-capable field, and the public pagination reference does not promise cursor stability across node upgrades. Eventide therefore requires an explicit `archiveCapable` operator flag and deduplicates by event ID.
